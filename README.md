# PARALLAX 폴더블 업무폰 프로토타입

경찰 작전 지원 서비스 PARALLAX의 현장 업무폰 화면입니다.
현장에서 놓친 장면과 눈에 보이지 않는 정보를 확인하고, 다음 인력이 바로 이어받을 수 있는
작전 기록으로 정리하는 작업 화면입니다.

커버 → 펼친 화면 → 2분할로 이어지는 폴더블 흐름을 따르고,
기기 비율은 아이폰 듀오 실측(펼침 164.6 × 117.8 mm)을 mm 단위로 그대로 씁니다.
시각 디자인은 Apple의 디자인 원칙을 참고해 조용하고 정교한 업무 도구로 구성했습니다.

> **모든 데이터는 `DEMO INCIDENT 01`의 가상 시나리오입니다.**
> 실존 사건·실제 기관·실제 인물·실제 장소·실제 영상을 사용하지 않았고,
> 어떤 시스템과도 연동되지 않습니다.

---

## 실행 방법

`index.html`을 브라우저에서 열면 됩니다. 설치도 빌드도 필요 없습니다.

```
open index.html
```

글꼴·스크립트·3D 모형이 모두 폴더 안에 있어 **인터넷 없이, 서버 없이** 동작합니다.
로컬 서버로 보려면 `python3 -m http.server 8777` 후 `http://localhost:8777`.

첫 진입은 **펼친 화면의 `장면 검토` 조합**입니다.
데모 조작(화면 전환 · 기기 색 · 접기 · 초기화)은 **기기 오른쪽 세로 바**에 모아 두었습니다.
위아래에 두면 기기가 쓸 세로를 잡아먹기 때문입니다.
기기를 직접 눌러도, 좌우로 끌어도 접히고 펴집니다.

각도를 고정해서 보려면 `index.html?fold=45` 처럼 붙이고,
모드를 강제하려면 `?mode=mock` 또는 `?mode=real` 을 붙입니다.

## 주요 UX 흐름

### 기기 비율과 접힘 모션
아이폰 듀오 실측을 mm 단위로 그대로 씁니다.

| 항목 | 값 |
|---|---|
| 펼친 본체 | 164.6 × 117.8 mm (1.397:1) |
| 접은 본체 | 84.1 × 117.8 mm — 반쪽 82.3mm 로 모델링 (1.8mm 힌지 등은 생략) |
| 내부 화면 | 157.8 × 110.9 mm |
| 커버 화면 | 77.2 × 112.3 mm |

`--mm` 하나를 화면 크기에 맞춰 정하고 나머지 치수는 전부 여기에 곱합니다.
그래서 목업과 실기기가 같은 비율로 나옵니다.
**펼치면 세로로 긴 폰이 가로로 넓은 화면이 됩니다.** 좌우 2단 배치가 이 비율에 맞습니다.

#### 목업 모드 (PC)
기기가 3D로 펴지고 접힙니다. 각도는 `--fold` 하나로만 움직입니다 (0 접힘 · 180 펼침).
`@property` 로 숫자 타입으로 등록해 두어 각도가 보간되고,
기울기·명암·중앙 보정·바닥 그림자는 전부 여기서 파생됩니다.

- 기기 바깥이나 테두리를 **누르면** 접히고 펴집니다
- **좌우로 끌면** 각도를 직접 잡을 수 있습니다 (오른쪽으로 밀면 덮입니다).
  손을 뗄 때 민 속도가 빠르면 그 방향으로, 아니면 가까운 쪽으로 붙습니다
- 안내 버튼에 초점을 두고 `Space`/`Enter` 토글, `←` `→` 로 15도씩
- 90도를 넘어가는 순간 커버 화면이 저절로 드러납니다.
  커버 면을 왼쪽 짝의 **뒷면**에 붙여 두었기 때문에 따로 전환하는 코드가 없습니다
- 접으면 오른쪽 반쪽만 남으므로 기기와 그림자를 그만큼 되밀어 가운데에 둡니다
- 접힐수록 안쪽 두 면이 어두워집니다. 빛은 열린 바깥쪽에서 들어옵니다
- `prefers-reduced-motion` 을 켠 환경에서는 보간 없이 바로 전환됩니다

살아 있는 화면 하나를 두 짝에 반씩 걸칠 수는 없으므로,
각도가 180이 아닌 동안에만 양쪽 면에 **복제본**을 얹습니다.
복제본은 `inert` 로 막아 두고 id·`data-fk` 를 지워서 초점과 id 를 훔치지 않습니다.
다 펴면 복제본을 치우고 진짜 화면을 돌려줍니다.

#### 실기기 모드
실제 폴더블에서 접고 펼 때 레이아웃만 갈아입습니다. DOM 을 다시 만들지 않으므로
스크롤 위치·입력값·초점이 그대로 살아 있습니다.

- 자세 판정: `navigator.devicePosture` 가 **`folded` 라고 답할 때만** 믿고,
  그 밖에는 `min-width: 700px` 로 봅니다. 데스크톱 크로미움도 `devicePosture` 를 갖고 있어서
  그것만 보면 PC 가 실기기로 빠집니다. 모드 판정도 `pointer: coarse` 와 화면 폭을 같이 봅니다
- 배치가 바뀔 때는 `document.startViewTransition` 으로 감싸고,
  상태 바에 같은 `view-transition-name` 을 주어 사라졌다 나타나지 않게 합니다
- `resize` 는 80ms 디바운스해서 마지막 상태만 반영합니다
- 힌지 위치를 OS 가 알려줄 때(`horizontal-viewport-segments: 2`)만
  2단의 폭을 `env(viewport-segment-width …)` 에 맞춥니다
- 3D를 완전히 걷어냅니다(`transform-style: flat`). 조상에 `perspective` 가 남아 있으면
  그 조상이 컨테이닝 블록이 되어 화면이 비어 버립니다

#### 기기 프레임
애플 공식 베젤 이미지(developer.apple.com/design/resources)를 쓰지 않고 CSS로 만들었습니다.

- **테두리**: 단색이 아니라 각도 그라데이션입니다. 밝은 하이라이트가 위아래 모서리
  0.4mm 지점에 놓이고 2.6mm 안에서 어두운 금속으로 꺾입니다.
  stop 을 %가 아니라 **mm 로 잡아야** 합니다. %로 잡으면 3mm짜리 얇은 베젤이
  그라데이션의 밝은 끝만 잘라 써서 테두리 전체가 하얗게 뜹니다
- **힌지**: 테두리와 질감이 다릅니다. 거울 광택 대신 평평한 무광에 아주 얕은 세로 결만
  둡니다. 접었을 때 왼쪽 등으로 드러나고, 펴면 안쪽으로 숨습니다
- **모서리**: `corner-shape: squircle` 은 `@supports` 안에서만 씁니다.
  지원하지 않는 브라우저에서는 `border-radius` 로 그대로 보입니다
- **베젤**: 펼침 좌우 3.4 / 상하 3.45mm, 접힘 좌우 3.45 / 상하 2.75mm.
  실측값 그대로이고 테스트가 이 숫자를 지킵니다
- **내부 화면에 노치도 다이나믹 아일랜드도 펀치홀도 없습니다** (언더디스플레이 카메라)
- **옆면**: 두께 5.2mm짜리 면을 `rotateY(90deg)` 으로 세웠습니다.
  바깥을 향한 쪽만 보이게 해서 정면에서는 비치지 않고, 기울일 때만 드러납니다.
  오른쪽 옆면에 측면 버튼과 볼륨 버튼이 붙어 있습니다
- **색**: Star White / Night Sky 두 가지. 데모 바에서 고르거나 `?tone=white|night`
- **유리 반사**: 각도에 연동합니다. 다만 **읽는 각도(다 편 상태·다 접은 상태)에서는 0**입니다.
  흰색을 6%만 얹어도 본문 색 대비가 4.5:1 아래로 내려가기 때문입니다.
  세기를 `--tilt`(90도에서 1, 양 끝에서 0)에 묶어 두었고,
  도는 쪽이 세게 받고 고정된 쪽은 거의 그대로입니다
- 애플 로고·워드마크는 넣지 않았습니다

화면 밖(바탕·데모 바·안내·주석)은 `prefers-color-scheme: dark` 를 따릅니다.
`?theme=dark|light` 로 강제할 수 있습니다. **기기 안 화면은 실제 기기 화면이라 그대로 둡니다.**

#### 크기
조작을 옆으로 뺀 덕에 기기가 창 세로를 거의 다 씁니다(약 94%).
기울면 가까운 쪽이 커 보여 창 밖으로 나가는데, 이건 **도는 동안만 살짝 물러서게**
해서(`scale: calc(1 - .14 * var(--tilt))`) 흡수합니다.
그래서 다 폈을 때의 크기를 깎지 않고도 45·110도에서 잘리지 않습니다.

#### 각도를 고정해서 보기
`?fold=0` `?fold=45` `?fold=110` `?fold=180` 으로 각도를 고정할 수 있고,
`?mode=mock` `?mode=real` 로 모드를, `?tone=` `?theme=` 로 기기 색과 바탕을 강제할 수 있습니다.

### 접은 화면 → 펼친 화면
커버에서는 새 특이 장면 건수와 가장 최근 장면만 크게 보여줍니다.
장면을 누르면 **선택 상태를 그대로 들고** 펼친 화면의 상세로 이어집니다.
접고 펼쳐도 선택한 장면, 지도 위치, 영상 재생 시점, 작성 중인 메모가 유지됩니다.
음성 기록은 길게 눌러 녹음하고, 다시 눌러 저장합니다.

### 장면 → 공간 → 음성 → 메모
- 특이 장면의 `지도에서 보기` → 왼쪽 평면도에서 해당 구역이 강조됩니다
- 지도에서 구역·마커를 고르면 영상·음성·메모가 그 구역으로 좁혀집니다
- 음성의 `메모로 인용` → 시간과 발신 역할이 들어간 메모 초안이 생깁니다
- 메모의 `팀에 공유` → 공유 상태로 바뀌고 토스트로 알립니다
- 장면의 `인계 메모에 연결` → 다음 인력이 받을 기록에 바로 묶입니다

### 멀티태스킹 — 2분할과 사이드 탭
작업 영역은 **세로로 가른 두 칸**입니다. 붙여 놓지 않고 둥근 창처럼 띄워
사이를 벌려서, 벌어진 틈으로 바탕이 비칩니다. 두 칸이 '떠 있는 것'으로 읽힙니다.

**탭은 켜고 끄는 스위치입니다. 눌러서는 두 칸이 되지 않습니다.**

| 무엇을 하면 | 어떻게 되나 |
|---|---|
| 꺼진 탭을 누르면 | 그 화면 **하나만** 열린다 (열려 있던 건 갈아 끼운다) |
| 켜진 탭을 다시 누르면 | 그 화면이 **꺼진다** |
| 다 끄면 | 빈 화면 안내가 나온다 |
| 탭을 **끌어다 놓으면** | 놓은 쪽에 앉아 **두 칸**이 된다 |
| `조합`을 고르면 | 저장된 두 칸 배치가 한 번에 들어온다 |

**놓은 자리에 쓰던 화면이 있으면 옆으로 밀어냅니다. 덮어쓰지 않습니다.**
끌어다 놓기는 '나누겠다'는 뜻입니다. 놓은 자리를 덮어써 버리면
두 칸으로 나누려던 것이 도로 한 칸이 됩니다.

| 놓은 자리가 | 어떻게 되나 |
|---|---|
| 비어 있으면 | 거기에 앉는다 |
| 쓰던 화면이 있고 **옆이 비었으면** | 쓰던 화면이 **옆으로 밀려나고** 두 칸이 된다 |
| 반대쪽에서 끌어 왔으면 | 두 칸이 **자리를 맞바꾼다** |
| 두 칸이 **다 차 있으면** | 놓은 칸만 바뀐다 (옆 칸은 그대로) |

무슨 일이 생길지는 놓기 전에 **놓을 자리에 적어 줍니다**
(`왼쪽에 놓기 · 쓰던 화면은 오른쪽으로`). 쓰던 화면이 사라지는지 밀려나는지는
손을 떼기 전에 알아야 합니다.

두 칸으로 나누는 길은 **끌어다 놓기와 조합, 두 가지뿐**입니다.
화면 안의 연결(`지도에서 보기`, `메모로 인용` 같은 것)은 예전처럼 옆 칸에서 열립니다 —
보던 화면을 빼앗지 않는 것이 그 동작의 목적이기 때문입니다.

**단계로 붙는 크기 조절**
두 칸 사이의 그래버는 테두리 있는 버튼이 아니라 **얇은 알약 하나**입니다.
잡으면 굵어지고 파래집니다.
끄는 동안은 손을 그대로 따라오고, **손을 떼면 `1/3 · 1/2 · 2/3` 중 가까운 단계로
스프링을 타고 앉습니다**(iPadOS 분할과 같은 단계). 아무 값에나 서지 않습니다.
`←` `→`(좁으면 `↑` `↓`)로 단계를 오가고, `Enter`나 두 번 누르면 반반으로.
비율 보간은 `@property --ratio` 를 숫자로 등록해서 CSS 가 직접 합니다.
끄는 동안만 보간을 끄고, 놓을 때 되살려 튕기듯 앉게 합니다.

**끌어다 놓기**
왼쪽 탭을 끌면 **집어 든 탭은 자리만 남기고 흐려지고**, 커서에는 아이콘과 이름이
얹힌 판이 따라옵니다. 두 칸은 살짝 물러나 자리를 내어 줍니다.
놓을 자리는 **점선 테두리가 아니라 은은하게 채운 둥근 면**입니다 —
점선은 애플 쪽 언어가 아닙니다. 커서가 있는 쪽만 파랗게 채워지고 테두리가 굵어집니다.
끌고 다니는 판은 `body` 에 붙입니다. 화면 안에 두면 3D 와 `overflow:hidden` 에 잘립니다.
끌지 않고 그냥 누르면 예전처럼 빈 자리에 열립니다.
(끌고 난 뒤 따라오는 `click` 은 캡처 단계에서 한 번만 삼킵니다.
플래그로 들고 있으면 놓을 곳이 없었을 때 다음 클릭까지 먹습니다.)

끄는 동안의 손짓은 **`window` 에서 받습니다.** 끄는 도중에도 화면은 다시 그려질 수
있고(영상이 끝난다든지), 그때 집어 든 단추와 놓을 자리는 죄다 헌것이 됩니다.
단추에 매달아 두면 그 순간 끌기가 조용히 끊깁니다. 자리 계산에 쓰는 요소도
움직일 때마다 지금 붙어 있는 것을 다시 찾아 씁니다.
손가락은 `touch-action:pan-y` 로 갈라 둡니다 — 세로로 쓸면 탭이 스크롤되고,
가로로 쓸어야 탭이 끌려 나옵니다. 풀어 두면 끌기가 스크롤에 잡아먹힙니다.

**자리가 바뀌는 것을 눈으로 따라가게 (FLIP)**
다시 그리면 DOM 이 통째로 새것이라 CSS 만으로는 움직임이 이어지지 않습니다.
그래서 바꾸기 **전에 각 칸의 자리를 재어 두었다가**, 새 자리에서 옛 자리로
되돌려 놓고 제자리로 보냅니다(`PX.act` 의 `morph`). 실제로 그려지는 것은
`transform` 하나뿐입니다.

- 밀려나는 칸은 **있던 자리에서 미끄러져** 옆으로 갑니다
- 폭이 크게 달라지는 동안에는 본문만 잠깐 흐려집니다. 늘어나는 글자를 감추면
  창틀이 모양을 바꾸는 것으로 읽힙니다. 제목 줄은 남겨 둡니다 —
  어느 칸이 어디로 갔는지 따라가야 하니까
- 닫힌 칸은 **있던 자리에 잠깐 남았다가** 사그라듭니다(`.pghost`).
  그냥 사라지면 눈이 놓칩니다. 이 잔상에서도 3D 모형은 빼냅니다
- `prefers-reduced-motion` 이면 이 전부를 건너뛰고 곧바로 바뀝니다

**한 칸만 열면 꽉 채운다**
한쪽을 닫으면 남은 창이 작업 영역 전체를 씁니다. 그래버도 같이 사라집니다.
넓어진 덕에 특이 장면 화면은 목록과 상세가 좌우로 갈라집니다.

좁은 화면에서는 두 칸이 위아래로 눕고, 그래버와 놓을 자리도 같이 눕습니다.

`조합`을 누르면 저장된 4가지 배치를 탭 옆에서 고를 수 있습니다.

| 조합 | 왼쪽 | 오른쪽 |
|---|---|---|
| 장면 검토 | 공간·영상 연결 보기 | 특이 장면 확인 |
| 음성 확인 | 특이 장면 확인 | 음성 기록 |
| 인계 준비 | 공간·영상 연결 보기 | 현장 메모장 |
| 장비 점검 | 현재 작전 상태 | AR 글래스 관리 |

큰 작업 화면은 한 번에 **2개를 넘지 않습니다.**
영상 재생 중 다른 기능을 열면 **PiP 플로팅 창으로 옮겨 재생이 이어집니다.**
플로팅 영상 아이콘은 **영상이 있는 화면에만** 둡니다. 없는 화면에는 아이콘 자체를 두지 않습니다.

### AR 글래스 3D 모형
`AR 관리` 화면 맨 위에 AR 글래스 3D 모형(`PARALLAX_AR_Glasses_ReferenceRebuilt_v3.glb`)이
올라갑니다. **끌었을 때만 좌우로 돕니다** — 위아래 각도와 거리는 건드리지 않습니다.

- **스크롤에 매달아 두지 않았습니다.** 내려 읽으면 다른 내용과 똑같이 같이 올라갑니다.
  붙잡아 두면(sticky) 보고 싶지 않을 때도 자리를 차지합니다
- 마우스로 끌거나 손가락으로 쓸면 돕니다. 가로로만 도는 것은 `min/max-camera-orbit` 의
  위아래 각도와 거리를 **같은 값으로 묶어** 둔 덕입니다 (`90deg`, `85%`)
- 손가락은 `touch-action="pan-y"` 로 갈라 둡니다. **세로로 쓸면 화면이 스크롤되고,
  가로로 쓸어야 모형이 돕니다.** 안 갈라 두면 모형 위에서는 화면이 안 내려갑니다
- `<model-viewer>` 는 `js/vendor/` 에 받아 두었습니다. 인터넷이 없어도 됩니다.
  다만 `file://` 에서 돌리려면 두 군데를 손봐야 했습니다
  (`js/vendor/model-viewer.classic.js`, 파일 첫머리에 적어 두었습니다)
  - 끝의 `export{...}` 를 떼어 **고전 스크립트**로 만들었습니다.
    `type="module"` 은 `file://` 에서 CORS 로 막힙니다
  - 통째로 함수에 감쌌습니다. 모듈은 제 울타리를 갖지만 고전 스크립트는 전역을 씁니다.
    이 번들이 최상위에 `const $` 를 선언하는데 `store.js` 의 `$` 와 부딪쳐
    `Identifier '$' has already been declared` 로 통째로 죽었습니다
- 모형은 `js/model-glb.js` 에 **data URL 로 실어** 두었습니다.
  `.glb` 를 따로 읽으면 `file://` 에서 막히고, 배포 쪽에서는 아예 서빙되지 않습니다.
  원본 `.glb` 는 폴더에 그대로 있고, 모형을 바꾸면 이 파일을 다시 만들면 됩니다
  (만드는 방법은 `js/model-glb.js` 첫머리에)
- **다시 그릴 때마다 새로 만들지 않습니다.** 하나만 만들어 두고 자리만 옮깁니다.
  새로 만들면 WebGL 맥락과 모델 읽기가 매번 되풀이됩니다
- 접히는 동안 보이는 복제본에서는 모형을 **빼냅니다**. 그대로 두면 WebGL 맥락이 세 개가 됩니다
- WebGL 이 없는 환경에서는 아예 만들지 않고 안내만 띄웁니다.
  만들면 라이브러리가 안에서 터집니다

## 만들지 않은 것

현장 화면이 지휘 권한을 대신하지 않도록 아래는 의도적으로 넣지 않았습니다.

- 특이 장면의 `확정` / `거부` 버튼 — 현장은 확인하고 기록만 남깁니다
- 지휘 지시를 수정·삭제하는 기능 — 할 수 있는 것은 `수신 확인`뿐입니다
- 관제실이 현장 AR 시야를 원격으로 바꾸는 기능 — 표시 설정은 착용자 본인만 바꿉니다
- 가짜 위성지도, 가짜 CCTV 사진, 가짜 경찰 문서 — 선형 평면도와 출처 표기로 대신했습니다
- 실제 기관 로고·계급·배지 표기

자동 전사는 `AI 전사 제안`이라는 보조 영역으로만 두고, 원본 음성 재생을 위에 배치했습니다.

## 유리 (글래스모피즘)

떠 있는 것은 뒤를 비칩니다. 상태 바 · 사이드 탭 · 목록판 · 평면도 · 영상 프레임 ·
Inspector · PiP · 조합 창 · 세그먼트 컨트롤이 모두 반투명 유리입니다.

- 유리는 **뒤에 비칠 것이 있어야** 유리로 읽힙니다. 그래서 화면 바탕에
  아주 옅은 그라데이션(파랑·하늘·주황, 각 **6%**)을 깔았습니다
- 그 기운 위에서도 본문이 4.5:1 을 넘도록 글자색을 한 단계씩 내렸습니다
  (`--secondary` `#6E6E73 → #67676C`, `--orange-text` `#9A5B00 → #975900`,
  `--green-text` `#1E7B34 → #1D7732`). 세 겹이 다 겹치는 최악의 지점을 기준으로
  계산했습니다
- 판마다 위쪽에 1px 하이라이트(`inset 0 1px 0`)와 둘레 0.5px 선을 둡니다.
  이 두 줄이 없으면 유리가 아니라 그냥 흐린 사각형으로 보입니다
- **접히는 동안 보이는 복제본에서는 `backdrop-filter` 를 끕니다.**
  같은 화면이 세 벌(양쪽 반쪽 + 진짜)이라 유리판이 스무 겹 넘게 쌓입니다.
  반투명은 그대로 남아서 겉보기 차이는 거의 없고, 도는 동안 프레임이 살아납니다

## 색을 쓴 규칙

지정된 팔레트를 그대로 쓰되, **채움·점·마커에 쓰는 값과 글자에 쓰는 값을 나눴습니다.**
Apple 시스템 색은 면과 글리프 기준이라 작은 글자로 쓰면 대비가 부족합니다
(`#FF9F0A`는 흰 배경에서 2.06:1).

| 용도 | 값 |
|---|---|
| 점·마커·스위치·채움 | `#007AFF` `#FF9F0A` `#FF3B30` `#34C759` (지정값 그대로) |
| 같은 뜻의 **글자** | `#0064CE` `#9A5B00` `#C0271D` `#1E7B34` (어둡게 조정) |

이렇게 해서 본문 15.5:1, 보조 4.7:1, 상태 글자 4.8:1 이상을 지켰습니다.
주요 조작은 44px 이상이고, 지도 마커·스위치처럼 작게 보이는 요소도 터치 영역은 44px입니다.
구역 상태는 색만으로 구분하지 않고 글자와 점선 테두리를 함께 씁니다.
